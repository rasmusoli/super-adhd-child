# Super ADHD Child Delegation Economics Design

## Goal

Tune the combined plugin to choose the cheapest sufficient execution topology
without weakening Superpowers' high-assurance workflows or ADHD's manual-first
boundary.

## Design

Keep `skills/using-superpowers/SKILL.md` as the single authoritative
collaboration policy. Replace the unconditional activation default with a
requirement to proactively evaluate delegation, then delegate only when work
is independently separable, a meaningful benefit exists, and that benefit is
likely to exceed assignment, handoff, waiting, review, repair, context
reconstruction, and wall-clock costs. Numeric token accounting is not required.

Use a compact topology ladder: direct execution for trivial, tightly coupled,
highly context-dependent, or faster-inline work; one Reader for bounded
read-only investigation; one Builder for bounded implementation with clear
acceptance criteria; independent review only for material risk or explicit
verification needs; selective parallelism only for genuinely independent
domains; and full subagent-driven development for approved multi-task or
high-assurance plans. Preserve fresh implementers, review gates, repair loops,
ledgers, final review, and branch finishing.

Add capability-aware waiting guidance: use native blocking or completion
events when available, never hard-code operation names, avoid short polling and
evidence-free status updates, and resume only on completion, blocker, defect,
meaningful timeout, or user intervention. Preserve file-based handoffs and
short return contracts.

Before delegating related multi-step work, inspect only the relevant approved
requirements, active plan, durable documentation, interfaces, tests, and
current behavior. Surface and resolve material contradictions at coordinator
level; do not perform repository-wide audits by default.

Keep `skills/using-super-adhd-child/SKILL.md` explicit that delegation is
separate from ADHD routing. ADHD remains manual-first and activates only for an
explicit ADHD/divergent-ideation request or genuinely broad ideation.

## Verification

Update repository contract tests to enforce semantic markers for economics,
topology, waiting, documentation consistency, and preserved safeguards. Update
release documentation and local-modification attribution only where needed,
rebuild `skill.zip`, and run repository validation, full tests, deterministic
freshness, offline drift, syntax/reference checks, and `git diff --check`.

## Cleanup boundary

Remove the two untracked documents that describe the superseded unconditional
activation policy. Do not rewrite historical checked-in plans or design
documents, and do not modify standalone Superpowers or ADHD installations.

## Non-goals

- No fixed model names, worker counts, wait operation names, or orchestration engine.
- No automatic global configuration changes, installation changes, or commits.
- No reduced verification solely to save tokens.
- No claims of token or latency savings without measurement.
